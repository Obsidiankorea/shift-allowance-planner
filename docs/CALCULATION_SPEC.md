# 계산 명세 — Excel 재현과 계획 시뮬레이션

상태: 코드 및 제공 Excel에서 확인한 산식. 법령 적합성 인증이 아님. 금액은 원, 시간은 시간 단위.

## 수식

```text
raw = 날짜별 근무/휴가/교육/출장 산입시간
    + 날짜별 추가 교육/출장/기타시간
    - 날짜별 제외시간
    + 비번활동 월 인정시간
    + 월 hours 조정값

total = floor(raw)                  # 엑셀 호환 기본값
base_days = 월~금 중 공휴일 제외 날짜 수
signed = trunc(total - base_days*8 - holiday_days*8 + basic_adjustment)
payable_hours = max(0, signed)

ot_pay      = trunc(payable_hours * overtime_rate / 10) * 10
night_pay   = trunc(night_hours * night_rate / 10) * 10
holiday_pay = trunc(holiday_days * holiday_rate / 10) * 10
pay = ot_pay + night_pay + holiday_pay
```

월 시간 절사는 엑셀 재현이면서, 수당규정 제15조⑤("1일 시간외근무시간은 분 단위까지 더하여 월별 시간외근무시간을 산정한 후 1시간 미만은 버린다")와도 같은 효과다 (공제항이 8시간 단위 정수이므로 floor(총시간) − 공제 = floor(시간외)). 2026-10-07 원문 확인. 10원 미만 절사는 엑셀 재현이다.

시간 절사를 끄면 `total=raw`, `signed`의 정수절사도 하지 않는다. 금액의 10원 미만 절사는 유지한다. 비번활동은 Excel이 월 합계를 먼저 ROUNDDOWN하는 특성이 있어 별도 활동 항목으로 관리한다.

## 중요한 경계 사례

- 초과 −50시간에 추가 8시간: 시간외 지급시간은 여전히 0. 야간·휴일수당은 변하지 않음.
- 초과 −50시간에 추가 51시간: 다른 조건이 같으면 지급 1시간. 절사 이전 소수점에 따라 최소 추가시간은 달라질 수 있음.
- 초과 0시간에 추가 0.5시간: 총시간 소수점 절사 때문에 증가액이 0일 수도 있고 1시간분이 될 수도 있음.
- 9.5시간 주간을 8시간 교육으로 대체: 총시간은 1.5시간 줄어듦. 휴일이었다면 휴일수당 대상일도 줄어들어 순효과를 다시 계산해야 함.
- 비번에 교육8시간: 총시간 +8시간. 휴일수당을 별도 새로 생성하지 않음.
- 주간9.5시간 유지하면서 추가교육8시간: 총시간 +8시간. 실제 시간 중복 여부는 사용자가 확인.
- 휴일9.5시간 근무를 합산하고 휴일수당8시간을 공제하더라도 1.5시간이 **항상 지급**되는 것은 아님. 월 전체 signed가 여전히 음수이면 시간외 지급액은 0.
- 월말 야간은 시작일에 15.5시간/야간8시간이 전부 귀속되는 모델. 기관의 다른 월 구분 기준은 추후 분리 구현 대상.

## 연가 vs 연가보상비 (1.1, 1.2에서 연가일 한정으로 변경)

시간 환산만 보면 주간 9.5시간 근무를 주연으로 바꾸면 8시간이 산입되므로 "8시간짜리 초과근무를 일하지 않고 얻는" 효과가 있다. 그러나 그 연가를 쓰지 않았다면 받을 연가보상비가 사라진다. 앱은 이 둘을 같은 원 단위로 비교한다.

```text
본봉(월봉급액) = 2026 봉급표[직급][호봉]      # 호봉 입력 시
               = 사용자 직접입력 본봉            # 호봉 미입력 시
연가보상비 1일 = 본봉 × 86% ÷ 30                # 비율·분모는 설정에서 변경 가능
                 (연가보상 대상 N이면 0원)

비교 대상 = 연가 차감일수 > 0인 코드 (기본 주연·야연·당연1·당연2)
  날짜 (달력에서 그 날을 선택했을 때):   leave_value
  월   (연간표 '연가 손익' 열, 그 달의 모든 연가일): month_leave_value

  gain = pay(현재 근무표) − pay(같은 연가일을 '비'로 비운 근무표)
  net  = gain − 연가보상비 1일 × 사용 연가일수
  손익분기 지급시간 = 보상비 ÷ 시간외단가
```

- 비교는 **달력에 실제로 연가를 넣은 날짜에만** 나온다. 근무일·비번일에는 표시하지 않는다. 연간표도 연가가 없는 달은 빈칸이다.
- 특별휴가·공가·병가(주특, 야공, 주병 등)는 연가일수를 차감하지 않으므로 보상비 기회비용이 없다고 보고 비교하지 않는다 (사용자 설명, 2026-10-07). 선택 시 "비교하지 않음" 한 줄만 표시.
- 대안은 "연가를 안 쓰고 그 날을 비움(0시간)"이다. 근무교환으로 다른 날 근무가 늘었다면 그 날짜도 따로 수정해야 한다. 그 날 직접 근무하는 경우와의 비교는 원래 근무표 대비 카드로 본다.
- `pay`는 기존 `calculate`를 그대로 쓴다. 시간외 0 하한, 월 시간절사, 10원 미만 절사가 반영된다. 비움과 비교하므로 야간·휴일수당은 연가·비움 모두 0이라 차이에 들어가지 않는다.
- 비교는 프로젝트 복사본에서 해당 날짜 코드만 '비'로 바꿔 계산한다. 교육·출장·기타 추가시간·비번활동·제외시간 필드는 유지하고 `credit/night/holiday/hours` 직접 지정값은 버린다. 저장된 수정안은 바뀌지 않는다. 연가 산입시간은 두 경우의 `raw` 차이로 표시하므로 날짜별 직접 지정 산입시간도 반영된다.
- 연가 사용일수 기본값: 주연·야연·당연1 = 1일, 당연2 = 2일 (`leave_days`, 설정 `연가 차감일수`). 수당 산입시간(야연 일반직 15/소방 8)과는 별개의 값이며, 실제 연가 잔여일 차감 기준은 미확정(L03)이다.
- 보상비는 원 미만을 절사하지 않은 계획값으로 비교하고 화면에는 반올림 표시한다. 실제 지급 시 원 미만 처리와 지급 기준일 현재 월봉급액·호봉은 별도 확인.
- 1.1의 "연가 1건을 아무 달에나 더해 보는" 월 가정 비교(야연/주연 선택 상자)와 근무/연가/비움 3안 비교는 1.2에서 삭제했다.

검증 예 (사용자 일반6, 본봉 3,580,000원 = 2026 일반6 11호봉, 시간외 13,692원):

| 상황 | 계산 | 결과 |
|---|---|---|
| 보상비 1일 | 3,580,000 × 0.86 ÷ 30 | 102,626.67원 |
| 비울 때 초과 −10h, 야연 15h | 지급 5h → 68,460원 − 102,626.67원 | −34,166.67원, 연가 안 쓰는 게 유리 |
| 비울 때 초과 0h, 야연 15h | 205,380원 − 102,626.67원 | +102,753.33원 |
| 비울 때 초과 0h, 주연 8h | 109,530원 − 102,626.67원 | +6,903.33원 |
| 손익분기 | 102,626.67 ÷ 13,692 = 7.50h | 연가 산입시간 중 7.5h 이상이 시간외로 지급돼야 이득 |
| 실제 10월 편성표에 10-04 야연·10-07 주특 입력 | 비울 때 −17h → 연가 −2h, 수당 증가 0원 | −102,627원 (연가 안 쓰는 게 유리), 주특은 비교 없음 |

## 변경 전후 손익 (1.3, 1.4에서 기준 2개로 분리, 1.5에서 두 번째 기준을 저장파일로 변경)

지금 계획을 두 기준과 **따로** 비교한다. 근무표 층은 `사용자 수정(overrides) > 엑셀 편성(baseline) > 주야비비 주기`이다 (`event(...,scenario,roster)`).

| 카드 / 연간표 열 | 기준 | 묻는 것 |
|---|---|---|
| 주야비비 원형 대비 | `change_value(base='cycle')`: 엑셀 편성과 수정 모두 무시한 순수 주야비비 | 연가·근무교환을 전혀 안 했다면? 엑셀에 이미 들어간 연가·교환까지 포함 |
| 「저장파일」 대비 변경 | `file_change_value(p,pid,y,m,ref)`: 저장한 시나리오 JSON의 같은 사용자 계획 | 그 파일을 저장한 뒤 더 바꾸면? |

- 1.4의 `현재 근무표(엑셀 편성) 대비`는 사용자 피드백으로 1.5에서 저장파일 대비로 바뀌었다. `change_value(base='roster')`는 domain에 남아 있지만 화면에서는 쓰지 않는다.
- 기준 저장파일 = 폴더 아이콘으로 고른 파일(`prefs.compare_file`), 없으면 지금 작업 파일(마지막 저장/불러오기, `prefs.last_file`). 파일 수정 시각이 바뀌면 다시 읽는다.
- 저장파일 쪽 금액은 **그 파일 자체의 설정**(단가·근무시간·조정값)으로 계산한다. 그래서 날짜가 같아도 설정 차이로 금액이 다를 수 있고, 화면은 "날짜 변경 없음 (설정·조정값 차이)"로 표시한다. 연가 차감일수와 연가보상비 1일은 현재 프로젝트 값을 쓴다.
- 사용자 대응: id → 이름+직급 → 이름 (`find_person`). 없으면 비교하지 않는다.
- 세 카드(연가일, 주야비비 원형, 저장파일)의 결과 뒤 `ⓘ 계산 근거` → `explain.explain_html`: 한 줄 요약, 바뀐 날짜별 `day_parts`(인정시간·야간·휴일), ①총근무−정규−휴일공제=초과, ②시간×단가=수당, ③월 봉급×86%÷30 × 연가 사용일수 차이, ④최종. 숫자는 모두 `diff_value`가 가진 `before/after`(`calculate` 결과, `rates` 포함)와 `base` 문맥에서 가져오며 새 계산 규칙을 만들지 않는다. 연가일 비교도 1.5부터 `diff_value`(기준 = 그 날을 '비'로 바꾼 복사본)를 쓴다.

```text
gain = pay(현재 계획) − pay(기준)                    # 기준 = calculate(...,False,roster=base=='roster')
연가 증감일 = Σ 연가 차감일수(현재 코드) − Σ 연가 차감일수(기준 코드)
net  = gain − 연가보상비 1일 × 연가 증감일
```

- 엑셀 편성이 없는 달은 두 기준이 같다. 두 번째 카드는 "위 결과와 같습니다"만 표시하고 연간표 두 번째 열은 비운다.
- 1.3에서 보고된 문제: 엑셀로 가져온 10월은 이미 연가·교환이 반영된 편성인데, 1.3은 그 편성을 "손대지 않은 근무표"로 보아 변경 없음으로 표시했다. 1.4에서 순수 주야비비 기준을 별도로 추가했다.
- 주말 근무를 더 서서 휴일수당·시간외가 늘어도, 연가를 하루 쓰면 그만큼 보상비가 줄어든다. 기준에 있던 연가를 근무로 되돌리면 연가 증감일이 음수가 되어 보상비가 더해진다.
- 월 조정값은 양쪽에 똑같이 들어가므로 손익에 영향이 없다. 엑셀 비번활동(activity)은 순수 주야비비에는 없으므로 주야비비 대비 변경으로 잡힌다.
- 변경 목록은 기준 event와 현재 event가 다른 날짜. 코드가 같고 시간·메모만 다르면 `n일 코드 수정`. 화면은 8개까지 보이고 나머지는 `외 n일`.
- 날짜 단위 `연가 vs 비움`과 질문이 다르다. 그쪽은 "이 연가를 안 쓰고 비웠다면"이다.

검증 1 (1.3, 엑셀 10월 사용자에 16일 야→야연, 17일(토) 비→주, 일반6 11호봉): 현재 근무표 대비 수당 +87,250원, 연가 +1일 −102,626.67원, 순 −15,377원.

| 항목 | 원래 | 변경 후 | 차이 |
|---|---:|---:|---:|
| 총근무 | 184 (184.5) | 193 (193.5) | |
| 공제 | 160 + 휴일 3×8 = 184 | 160 + 휴일 4×8 = 192 | |
| 초과 | 0 | +1 | 시간외 +13,690 |
| 야간 | 56h | 48h | −36,510 |
| 휴일 | 3일 | 4일 | +110,070 |
| 수당 합계 | 585,770 | 673,020 | +87,250 |
| 연가 | 0일 | 1일 | 보상비 −102,626.67 |
| 순손익 | | | **−15,377원 (손해)** |

검증 2 (1.4, 엑셀 10월 직원 D, 엑셀에 9일(한글날) 주연 포함, 화면 확인용으로 일반5 14호봉 가정):
- 수정 없음: 주야비비 대비 `9일 주→주연`, 초과 +8 → +14h, 수당 −32,730원(시간외 +96,320, 휴일 −129,050), 연가 +1일 → 순 −163,046원. 현재 근무표 대비는 "추가로 바꾼 날짜 없음".
- 14일 야→야연 추가: 주야비비 대비 2일 변경, 연가 +2일, 순 −336,172원. 현재 근무표 대비 `14일 야→야연`만, 수당 −42,810원(야간), 순 −173,126원.

달력 머리줄의 `정규근무 n일 · n시간`은 `calculate`의 `base_days`와 그 × 8이다.

## 수정 손익 알림과 변경 히스토리 (1.7)

날짜 편집·수정 취소·월 조정값·설정·직급/호봉 변경 때마다 `Main.record_change`가 **수정 직전 프로젝트 복사본**을 기준으로 `diff_value(현재, pid, 그 달, 직전 복사본, 직전 사용자, True, True)`를 계산한다. 즉 손익 = 그 달 수당 차이 − (연가 차감일수 증감 × 연가보상비 1일). 결과는 오른쪽 위 알림(6초)과 이번 실행의 변경 히스토리(메모리, 저장 안 함)에 남고, 둘 다 `explain_html`로 계산 근거를 연다 (기준 이름 "수정 전 (변경 내용)"). 날짜 편집은 그 날짜의 달, 월 조정값·설정·호봉 변경은 화면에 보이는 달을 기준으로 한다. 엑셀 가져오기·불러오기는 기록하지 않는다.

## 근무 증감 대비 손익 (1.8)

`explain.hours_effect(cv)`: 근무 인정시간 변화 `dh = after.raw − before.raw`(|dh| ≥ 1일 때), 시간외 지급시간 변화 `paid = max(0,after.signed) − max(0,before.signed)`, 마이너스로 흡수된 시간 `absorbed = (after.signed − before.signed) − paid`. 휴일 8시간 공제로 빠진 시간은 absorbed에 넣지 않는다. |absorbed| ≥ 1이면 손익 알림과 계산 근거 요약에 "근무 X시간 감소(증가), 시간외 반영은 Y시간뿐, 줄인(늘린) 1시간당 Z원 (시간외 단가 W원)"을 표시한다. 예: 10/16 야→비 −63,890원 = 시간외 2시간분 −27,380원 + 야간 8시간분 −36,510원. 근무 15.5시간을 줄였지만 시간외에 반영된 것은 2시간뿐(초과 +2 → −14)이고, 1시간당 약 4,122원이다.

## 화면 표시 (1.2)

달력 옆 맨 위에 월 산식을 총근무와 공제를 나란히 보여준다.

```text
총근무  182시간  (182.5 절사)
공제    184시간 = (20일 × 8시간) + ^휴일(3일 × 8시간)      # ^휴일은 윗첨자, 휴일 0일이면 생략
초과     -2시간   시간외수당 0원 (음수)
시간외 0원 · 야간 48h 219,070원 · 휴일 3일 330,190원
```

`월 조정값`의 기본시간 가산이 있으면 공제 식 끝에 `− 가산 n시간`을 붙인다 (`calculate`가 `basic`을 반환). 그 아래 선택 날짜 카드에 날짜·근무코드·공휴일·수정 여부·메모와, 연가일이면 연가 비교를 표시한다. 산식 근거·색 범례·가정은 상단 `?` 도움말(`문서/도움말.md` → `산식과 근거.md`)에 있다.

salary_table (선택): {year, table{직급:[1호봉..]}} — 설정 → 봉급표에서 내장표와 다르게 저장했을 때만 존재

1.0 저장파일에는 `step/leave_comp/leave_days`가 없다. 모두 기본값으로 읽으므로 그대로 열린다. 봉급표는 기본적으로 `pay_tables.py`(내장표)를 쓰고, 프로젝트에 `salary_table`이 있으면 그것을 쓴다 (`salary_table(p)`). `salary_outdated(p,today)`는 올해 > 봉급표 연도일 때 참.

프로젝트 JSON과 별도로 PC별 화면 설정을 `%LOCALAPPDATA%\ShiftAllowancePlanner\prefs.json`에 둔다: `last_file`(작업 파일), `compare_file`(비교 기준 파일), `default_user`{id,name}, `skip_user_dialog`. 저장 여부 판단은 마지막 저장 상태의 JSON 스냅샷과 현재 프로젝트를 비교한다. `저장 안 함`으로 종료하면 autosave를 마지막 저장 상태로 되돌린다.

조회 우선순위: 사용자 수정 → 엑셀 입력 → 주기 자동 생성. 월이 바뀌어도 주기를 1일부터 다시 시작하지 않는다.

Event의 `hours`는 교육/출장으로 대체한 시간. `education`, `travel`, `extra`는 추가시간. `activity`는 원본 비번활동 시간. `credit`, `night`, `holiday`는 날짜별 직접 지정값. `memo`는 설명.

## Excel 좌표와 산식 근거

### 9월 수당표

- 날짜: `월중 근무내역` 2행 H~AK (날짜형 셀 탐지).
- 명부: 같은 시트 B 조, C 직급, D 이름, 6~17행.
- AM 휴가일수, AN 교육, AO 관외출장, AP 기타시간, AQ 주간제외, AR 야간제외, AS 추가시간.
- AS = 비번활동 I열 인정시간을 이름별 합계 후 ROUNDDOWN(...,0).
- AP = 날짜 셀 숫자합계 − AQ − AR + AS.
- 수당 산출 시트 N = 월총시간 ROUNDDOWN(...,0).
- O = NETWORKDAYS로 구한 기준일수, P = N−O×8+M, Q = TRUNC(P−J×8,0).
- R = 야간근무 횟수×8 − AR.
- U 시간외는 Q가 음수이면0, V 야간, W 휴일, T 합계. 금액 각 10원 미만 절사.
- 기존 파일의 M 기본시간은 대부분 빈칸/0. 프로그램은 월 `basic` 조정으로 보존.
- AP를 통째로 활동시간에 다시 더하지 않도록 활동과 숫자입력의 잔여를 월조정값으로 분리.

### 10월 편성표

- 날짜 A열은 주간 행에만 존재하므로 야간 행에서 직전 날짜를 유지.
- C 근무, D 조, F/H/J 실제 이름, K 비고.
- 시트2 E 소속조, F/G 반장 직급/이름, H/I 반원1, J/K 반원2.
- `행정 6급`, `방재 6급` 등은 단가 분류 `일반6`으로 정규화. 이름의 공백 제거.
- 동일 인물이 같은 날 둘 이상 근무하면 `복합`으로 합산하고 경고.
- `이름+연가/교육/출장/공가/특가/병가` 비고의 제한된 패턴을 해석.
- 기본명부에 없는 이름은 오류. 임의로 다른 직원과 합치지 않는다.
- 수식 캐시는 openpyxl data_only로 읽는다. Python이 Excel 수식을 재계산하는 것은 아니다.
